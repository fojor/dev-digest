Append-only log: entries are only ADDED to the end of a section via `node .claude/skills/engineering-insights/scripts/insights.mjs append`; existing ones are never edited or deleted (the guard hook blocks Write/Edit that change text).
Format: `- YYYY-MM-DD · <area> · <fact/symptom> → ALWAYS/NEVER <action>, because <reason> · <evidence: path + symbol / command / error text>` (trailing `[?]` = hypothesis, not yet confirmed).
Selection rules, review and promotion to CLAUDE.md — skill `engineering-insights`. This is a draft under human review, not the truth.

## What Works

- 2026-11-26 · SDD pipeline across sessions · another session can commit an upstream stage (clarify, ux-flows) to the same feature folder while this one is writing the next stage, and the files already read in context silently go stale → before the critic/commit step of any SDD stage, run 'git log --oneline -5 -- docs/features/<slug>' and diff the upstream docs against what you read, because the critic of a downstream doc otherwise reports dozens of 'drift' findings that are really missed upstream changes · conventions-extractor design: clarify 2041dcf + ux-flows 01824a0 landed mid-design; 9 SAD critic findings traced to them
- 2026-11-26 · SDD pipeline resume · a stage's output can already be on disk but uncommitted (an interrupted earlier run of the same stage left a half-written section in spec.md, and a LATER stage's tasks.json/tasks/ sat untracked with a task the owner had since ruled out) → before starting any SDD stage run 'git status --short -- docs/features/<slug>' and 'git diff -- <its target doc>', resume from what is there instead of regenerating it, and flag any downstream untracked output that conflicts with a decision, because the skill's protocol assumes a clean start and would otherwise duplicate the section or leave implement to build a dropped task · conventions-extractor plan-tests 22e4a80: half-done '## Test plan' in spec.md, T14 e2e still in untracked tasks.json
- 2026-11-26 · collapsing an SDD feature folder after it ships · the house format for a finished feature is one docs/features/<slug>/spec.md 'spec & implementation record' (run-cost, skills style: Problem / Goal table / Decisions table / Behaviour / API / ACs with test evidence / Implementation record / Open points), so the SDD artifacts (sad, adr, tasks, contracts, migrations…) get deleted — but INSIGHTS.md entries cite those files as evidence and AC ids get renumbered → before deleting, run 'grep -rn "docs/features/<slug>/" --include=*.md .' outside the folder, fold the ADR decisions and SAD risks into the Decisions table and Open points, and list the now-dangling INSIGHTS references for the owner, because nothing else catches them and the evidence trail silently breaks · conventions-extractor: server/INSIGHTS.md cites contracts/api-sync-report.md and spec AC-19/AC-20 (now AC16), root INSIGHTS cites ux-flows.md

## Recurring Errors & Fixes

- 2026-11-20 · dev.sh + pnpm ≥11 · ERR_PNPM_VERIFY_DEPS_BEFORE_RUN on client 'pnpm dev': pnpm ≥11 no longer reads the "pnpm" field (client/package.json pnpm.overrides) → run the client with 'npx -y pnpm@10 dev' or move overrides into client/pnpm-workspace.yaml, because pnpm 12 refuses to start rather than silently dropping the overrides · client/package.json, scripts/dev.sh
- 2026-11-20 · dev.sh + Docker · if the first 'docker compose up' fails on a port conflict (5432 taken by another project's Postgres), the devdigest-postgres container stays 'created'; the next dev.sh run does 'docker start' on it → healthy but with NO port mapping, and migrations fail ECONNREFUSED → free the port, then 'docker compose up -d --force-recreate' (keeps the volume; never 'down -v'), because the port binding is fixed at creation time · scripts/dev.sh Postgres section, 'docker port devdigest-postgres'
- 2026-11-24 · PR gate · 'gh pr create' (or 'git push' on a branch with an open PR) is refused by the PreToolUse hook with 'needs a PASS verdict for the current diff', even right after a review, whenever ANY tracked or untracked file changed since that review (the verdict is keyed by the exact diff hash) or the review used another --base → re-run /pr-self-review on the final tree as the very last step before opening the PR, and set PR_SELF_REVIEW_BASE in Claude Code's env for a non-main base, because the hook recomputes the hash against origin/main every time · .claude/skills/pr-self-review/hooks/pr-gate.mjs, .claude/settings.json
- 2026-11-24 · optional git pre-push gate · with install-git-hook.mjs installed, a push to a branch with an open PR is refused ('no pr-self-review verdict') even right after a PASS when the review ran with uncommitted or untracked files, because the git hook hashes the PUSHED COMMIT (diffHashForCommit) while the review hashed the working tree, and they are equal only for a clean tree → commit (or stash) everything first, then run /pr-self-review on the clean tree, then push; the Claude PreToolUse gate alone would accept the dirty-tree review, the git hook will not · .claude/skills/pr-self-review/hooks/git-pre-push.mjs, scripts/collect.mjs diffHashForCommit
- 2026-11-25 · PR gate after a commit · a PASS for a dirty tree stops matching right after 'git commit' even with byte-identical content (51a9af41… → 56f5fada…), so 'git push' to a branch with an open PR is refused, because collect.mjs hashes untracked files as synthetic '--- /dev/null' diffs while committed new files hash as real git diffs → when the change has new files, commit FIRST and run /pr-self-review on the clean tree, then push; reviewing before the commit costs a second full review · .claude/skills/pr-self-review/scripts/collect.mjs untracked branch, lab-02 commit 221fd3e
- 2026-11-27 · PR gate + agent-driven push · the assistant cannot produce the PASS itself: pr-self-review has disable-model-invocation, so the Skill tool refuses it ('cannot be used with Skill tool … Ask the user to run /pr-self-review'), and every new commit invalidates the previous verdict → when a task ends in a push to a branch with an open PR, batch ALL edits into the commit(s) first, then ask the user once to type /pr-self-review, then push, because each extra commit after the review costs the user another full review round · lab-02 commits 16c02e6 and c04287b each needed a separate user-run review
- 2026-11-27 · allowlist PreToolUse Bash hooks · splitting the raw command on /&&|\|\||;|\|/ denies harmless reads like jq '.skills|keys' (the | is inside quotes), and a naive quote mask that blanks everything inside double quotes lets echo "$(rm x)" through, because the shell still expands $( and backticks inside double quotes → mask single-quoted text fully, keep $( and backticks inside double quotes, split and check redirects on the masked string, deny on unterminated quotes (fail closed), and export checkCommand so an allow/deny table can be run with node -e before wiring the hook, because both bugs only showed up in that table · .claude/agents/hooks/readonly-bash.mjs maskQuotes/checkCommand, 29-case table run
